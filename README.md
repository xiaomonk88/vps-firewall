# vps-firewall

适用于 Debian 12 / 13。按管理地址、省份、网段、单个 IP 限制 VPS 入站，提供中文终端菜单。只过滤 IPv4，默认同时保护 Docker / NAT 映射端口。

> **只过滤 IPv4。** 1.3.0 起本程序不处理 IPv6：IPv6 流量不经过本程序，既不放行也不拦截。如果 VPS 有公网 IPv6，而系统里没有其他防火墙或云安全组，所有端口都可以通过 IPv6 直接访问；需要时请在云安全组中关闭 IPv6 入站，或在系统中禁用 IPv6。

## 从 GitHub 一键安装

仓库：[xiaomonk88/vps-firewall](https://github.com/xiaomonk88/vps-firewall)。适用于 Debian 12/13，需要先发布至少一个正式 Release。

首次准备下载工具（仅需执行一次）：

```bash
sudo apt-get update && sudo apt-get install -y curl ca-certificates python3
```

复制下面整行执行，下载完成后安装最新正式版本；安装过程中可能询问管理 IP：

```bash
(set -e; f=$(mktemp); trap 'rm -f -- "$f"' EXIT; curl -fsSL --retry 3 https://raw.githubusercontent.com/xiaomonk88/vps-firewall/main/github_install.py -o "$f"; sudo python3 "$f")
```

需要明确指定管理地址时，在末尾 `sudo python3 "$f"` 后加 `--rescue '你的管理IP'`。安装后用 `sudo vps-firewall` 打开菜单。

## 更新版本

打开 `sudo vps-firewall`，在主菜单选择 `9 更新与卸载 → 1 更新程序`，确认后即可更新，完成后自动重新打开菜单。也可以使用命令：

```bash
vps-firewall version              # 查看当前程序版本
vps-firewall --version            # 同样可以查看版本，无需 sudo
sudo vps-firewall update          # 更新到最新正式 Release
sudo vps-firewall update --tag v1.3.0  # 指定版本
```

更新保留现有配置和数据，更新前备份程序及配置到 `/var/backups/vps-firewall/`。仅推送 GitHub 代码不会让 VPS 自动更新。还没有 `update` 命令的版本可重新运行一键安装命令。

本地开发、上传代码和发布新版本的步骤见 [程序功能说明.md](程序功能说明.md) 第 11 节。

主菜单、子菜单标题和运行状态都会显示当前程序版本。主菜单顶部同时显示本版修改日期，例如 `vps-firewall  v1.3.0 · 2026.09.30`；日期随版本发布维护，不是当天日期或安装日期。版本号统一读取程序目录内的 `VERSION`，正式发布的 GitHub 标签与它保持一致。

## 手动上传、安装、打开菜单

把整个目录上传到 VPS，进入该目录执行：

```bash
sudo bash install.sh
sudo vps-firewall
```

首次安装会尝试识别当前 SSH 来源作为管理地址，支持自定义 SSH 端口。管理地址只能是 IPv4；通过 IPv6 登录时不会自动保存，会提示输入 IPv4 管理地址。也可以直接指定：

```bash
sudo bash install.sh 你的管理IP
# 多个管理地址用逗号分隔：
sudo bash install.sh '管理IP1,管理IP2'
```

重复安装保留已有配置。安装会自动安装依赖、校验并应用规则、启动服务和设置开机恢复。`sudo vps-firewall menu` 也能进入菜单。

| 工具 | 6 | 检查 IP | 查询某个地址能否访问本机，列出覆盖线索，可连续检查 |
| | 7 | 高级设置 | 映射端口保护，显示检测间隔和省份刷新周期 |

配色统一为四种：功能文字（编号、功能名、标题、条目、数量）为白色，说明、提示、备注和边框为灰色；状态只用绿色和红色——绿色 ● 表示开启 / 启用 / 成功，红色 ○ 表示关闭 / 暂停 / 失败。颜色仅在交互终端启用；重定向输出、`TERM=dumb` 或设置 `NO_COLOR` 时为纯文本。卡片宽度随终端在 46–68 列之间自适应，中文按显示宽度对齐，长地址和备注自动折行，标点不落在行首。

保存的开关与实际规则不一致时，横幅显示红色“▲ 未生效 / ▲ 未关闭”，主菜单下方给出提示，`4` 变为“恢复防护 / 关闭残留规则”，按保存的开关重新应用规则，不改变保存的设置。

### 名单页面

名单页面顶部说明用途，“当前条目”卡片预览最多 5 项，每项后面显示备注；IP、网段、省份白名单右侧显示“● 启用 / ○ 暂停”。操作只有两项：

- `1 添加`：可批量添加，三类白名单添加后逐条填写备注；添加页给出输入示例。
- `2 管理条目`：按“编号 / 条目 / 状态 / 备注”列出全部条目，每页 12 项，`n` / `p` 翻页，编号跨页保持一致。输入编号选中条目（可多个或范围，如 `1 3`、`2-5`），再选择操作：`1 修改备注`、`2 暂停`、`3 启用`、`4 移除`。操作完成后回到列表，可继续选择下一批。

禁止 IP 和直通 IP 没有备注和暂停，选中后直接进入“解除禁止 / 移除”的确认。只有管理条目时才显示条目编号，避免与操作编号混淆。

省份在一屏网格中按列编号，`✔` 表示已添加并启用，`停` 表示已添加但暂停，可按编号或名称多选。

### 白名单备注

添加 IP、网段或省份后，可逐条填写备注，例如“张三手机”“办公室网络”“广东客户”。回车跳过备注，输入 `0` 取消整次添加；批量添加也会逐条询问，每条显示为一张“第 N / M 项”卡片。备注最多 120 个字符。

在对应名单页面选择 `2 管理条目`，选中条目后选 `1 修改备注` 即可修改：回车保留，`-` 清空，`0` 取消整次修改。重复添加已有条目会保留其原备注。删除白名单时同时删除该条目的备注。

备注保存在同一份配置文件的 `notes` 分类中，会随配置备份和回滚。备注不会作为 IP、网段或省份参与规则生成。

### 暂停与启用条目

在 IP、网段或省份白名单内选择 `2 管理条目`，选中条目后选 `2 暂停` 或 `3 启用` 并确认即可，支持批量选择。暂停保留条目及备注，重新启用无需重新添加；重启、更新和配置备份都会保留状态。旧配置和新添加的条目默认启用，重复添加或修改备注不会自动启用已暂停条目。

暂停只停用选中的放行来源。如果地址仍被其他启用的 IP、网段、省份、直通 IP 或访问设置放行，它仍可能访问；需要明确拦截时使用“禁止 IP”。暂停不修改直通 IP 和禁止列表，启用条目也不会解除禁止。

### 维护、更新与卸载

“维护与日志”分“查看”（`1 运行状态`、`2 最近日志`、`3 本地省份包`）和“操作”（`4 刷新省份数据`、`5 恢复上一版`，右侧显示备份时间）两组。

`3 本地省份包` 列出本机实际已下载的省份、网段数量和缓存更新时间，并区分“启用 / 暂停 / 未选用”。已暂停或移出白名单的本地缓存也会列出，损坏或无法读取的包会标记异常。此页面只读，不会下载或修改防火墙。省份缓存文件本身不会放行任何地址，只有在省份白名单中启用的省份才参与规则。

`9 更新与卸载` 显示当前版本、发布日期和安装位置，提供 `1 更新程序`、`2 卸载程序`，均需 `1` 确认。卸载成功后退出菜单，备份位置保留在终端输出中；更新或卸载失败也会退出菜单并显示错误，避免继续使用可能已被替换或删除的程序。

`0` 返回或取消；确认操作显示在“请确认”卡片中，`1` 确认、`0` 或直接回车取消。保存结果直接显示在当前页面，不必反复按回车。主菜单和操作菜单直接按回车只刷新当前页，不会退出。每次修改立即校验、保存并生效；失败时保留或恢复旧规则。开启防护必须保留至少一个直通 IP，涉及当前 SSH 权限会提示确认。

## 删除 IP 后的行为

删除后，若该 IP 不在其他白名单中，新的访问和既有入站连接的后续流量都会被拦截，不必重启服务或等待连接自然过期。程序不会再偷偷把当前 SSH 来源加入名单。

若该 IP 仍属于已放行的省份、网段或管理地址，菜单会说明原因，并提供：

- **彻底撤销权限**：加入禁止列表；重复的单 IP 管理地址会一并移除，但必须保留另一个管理地址。
- **仅删除条目**：保留其他名单对它的放行。

也可以直接通过主菜单 `2` 禁止指定 IP。禁止地址不能与直通 IP 重叠；如果位于管理网段中，需要先调整管理网段。

删除权限后的 TCP 连接可能显示为超时，而非立即显示“连接关闭”；规则会丢弃它后续的入站数据。

## 公网 Ping

公网 Ping 有三档，在主菜单按 `5` 选择，或用 `sudo vps-firewall ping off|whitelist|all` 设置：

- **全部禁止（off）**：任何来源都不能 ping 本机，包括白名单和直通 IP；本机自己 ping 自己不受影响。
- **仅白名单（whitelist，默认）**：只有启用中的白名单和直通 IP 能 ping。
- **所有人（all）**：任何来源都能 ping，禁止 IP 除外。

三档只影响 IPv4 的 ping（ICMP echo-request），不影响业务端口，也不影响 IPv6 ping；ping 通也不代表业务端口能访问。从旧版本升级时自动换算原设置：原来开启的变为“所有人”，原来关闭的变为“仅白名单”。注意命令 `ping off` 的含义已改为“全部禁止”，旧脚本中表示“仅白名单”的 `ping off` 需改为 `ping whitelist`。

## 从 1.2 及更早版本升级（IPv6 相关）

1.3.0 去掉了全部 IPv6 功能，升级时自动处理：

- 旧规则表 `inet vps_wl`（同时过滤 IPv6）在第一次应用新规则时于同一事务中删除，换成只过滤 IPv4 的 `ip vps_wl`；此后 IPv6 入站不再受本程序限制。
- 配置中的 IPv6 条目（白名单、网段、禁止 IP、直通 IP 及其备注和暂停状态）以及 `allow_all_ipv6` 开关不再起作用，应用时自动从配置文件中清除，并在日志中列出清除了哪些内容。**原来禁止的 IPv6 地址从此不再被拦截。**
- 若直通 IP 只有 IPv6 地址，升级前的校验会失败并提示，旧版本保持运行；请先在配置中添加一个 IPv4 管理地址再升级。
- 菜单或命令中输入 IPv6 地址会直接报错，不会被保存。

## 常用命令

```bash
sudo vps-firewall                # 中文菜单
sudo vps-firewall status         # 配置、规则表和服务状态
sudo vps-firewall test           # 校验，不修改规则、配置或缓存
sudo vps-firewall reload         # 应用当前配置
sudo vps-firewall reload --force # 刷新省份数据后应用
sudo vps-firewall rollback       # 恢复上一版成功配置及本程序规则
sudo vps-firewall ping off       # 公网 ping 全部禁止（包括白名单）
sudo vps-firewall ping whitelist # 仅白名单可 ping（默认）
sudo vps-firewall ping all       # 任何来源都可 ping（on 等同 all）
sudo vps-firewall ping           # 查看公网 ping 当前状态
sudo journalctl -u vps-firewall -f
```

配置文件是 `/etc/vps-firewall/config.toml`，也支持手动编辑后自动重载。下载失败且没有可用省份缓存时拒绝本次应用，保留现有规则。菜单能显示配置是否与上次成功规则一致；配置写坏时可从菜单恢复最近一次成功配置。

## 关闭与卸载

临时或长期关闭过滤：在主菜单中选择 `4` 防护总开关。关闭状态会保存，重启后保持关闭；只解除本程序的规则。

卸载程序：在主菜单选择 `9 更新与卸载 → 2 卸载程序` 并确认。也可以使用命令：

```bash
sudo bash /opt/vps-firewall/uninstall.sh
# 或在上传目录执行：sudo bash uninstall.sh
```

卸载会询问确认，删除本程序的规则、服务和安装文件。配置、缓存、历史会先备份到 `/var/lib/vps-firewall-uninstalled.XXXXXX/`，实际路径会打印出来。其他防火墙表保留。

## 保护范围与验证

如果曾安装旧版 `vps-whitelist`，旧服务与新版共用规则表，同时运行会互相覆盖。1.0.8 起安装器会停用识别出的旧服务，保留旧配置及文件。可用 `sudo vps-firewall status` 查看保存的开关、实际规则和旧服务冲突提示。后台若反复报告规则丢失恢复，请检查是否仍有其他程序清理规则。

- 保护 VPS 本机所有端口的 IPv4 入站。规则表为 `ip vps_wl`，IPv6 流量不经过本程序。
- 默认对经过 DNAT 的映射端口应用同一白名单，可在“高级设置”中关闭。普通路由转发、无 NAT 的容器直连、云安全组不由本程序管理。
- 服务器主动发起连接的响应流量可以返回；显式禁止 IP 会同时阻止该来源的响应。
- 本程序放行不代表其他防火墙也会放行。
- 省份归属依赖外部 IPv4 数据，不保证定位准确。
- 本地回归测试在 Windows 上执行；Linux 真实网络测试已提供，当前工作环境未执行。安装脚本会在目标 VPS 上使用 `nft -c` 校验规则，不能代替完整连通性测试。

详细实现、修复清单和测试方法见 [程序功能说明.md](程序功能说明.md)。
